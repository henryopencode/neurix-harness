# Agent Note: 桌面语音控件保留单一音频所有者

Status: implemented

[English](2026-11-16-desktop-voice-controls.md) | 中文

## 问题

最小化后的语音对话需要可见的麦克风和播放控件。在原生窗口中另建浏览器音频生命周期，会拆散权限、中断、Session 保留和清理的所有权。

## 决策

主渲染进程拥有录音、合成播放和保留的 Session。原生窗口投影带修订号的阶段与静音状态，并把固定控制命令传给该所有者。其隔离文档不接收识别文字、Session 标题或运行任务列表。IPC 同时校验所属窗口及顶层 frame 来源。

可选输入框操作仅替换空闲且没有内容时的主操作。发送、停止、重试与附件提交仍由输入框所有。准备资源和输入偏好位于插件页，打开该页不会开始录音或下载。

桌面最小化保留主渲染进程的音频生命周期，并暂时关闭其后台限流。音频释放完成后，才撤回原生控件投影并释放 Session 保留句柄。纯浏览器页面隐藏时停止音频。原生渲染失败时还原主窗口，并请求结束音频。

## 考虑过的替代方案

第二个录音器会接受独立输入，需要跨窗口协调轮次。最小化时转移音频所有者会中断浏览器权限和播放状态。只投影阶段的原生窗口保留了既有 Session 输入路径和麦克风所有者。

## 影响

原生 UI 能力是可选的，旧桌面壳和普通浏览器继续只在前台运行音频。原生窗口延迟创建，不连接模型或 Host。[显式识别 Provider](2026-09-16-experimental-voice-input.zh.md)仍拥有识别位置和资源准备。

验证覆盖输入框回退、设备权限清理、原生窗口延迟加载、来源拒绝、麦克风与扬声器控制、修订顺序和音频释放等待。平台安装与真实麦克风验收仍按每次发布单独记录。
