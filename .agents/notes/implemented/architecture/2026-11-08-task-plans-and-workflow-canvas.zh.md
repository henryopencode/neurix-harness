# Agent Note：任务计划与工作流执行证据

Status: implemented

[English](2026-11-08-task-plans-and-workflow-canvas.md) | 中文

## 问题

工作流成员事件描述已经开始的子级，无法标识尚在计划中的工作、任务之间的前置依赖，或主 agent 执行的工作。根据成员启动顺序组装画布，会暗示执行从未声明的依赖。

## 决策

现有 todo 所有者在每次整表替换中记录可选的稳定任务 id、阶段、明确前置依赖、完成标准、子 Session 引用和结果。所属轮次标识同一份持续更新的计划。私有投影跟踪该轮次，并提供既有列表视图；缺少轮次身份的历史记录仍可读取。

计划工作与执行成员关系保持独立。任务可以没有子级，子级引用也不代表成功。已记录的工作流成员结果决定显式关联任务的显示执行状态；新的计划更新取代较早的成员结果，历史运行保留各自状态。未关联任务保留声明的计划状态。阶段名称不施加调度顺序，前置依赖校验也不调度执行。

画布拥有自己的 Conversation Definition 和 target，不读取 Chat 节点，也不扫描 Session 事件窗口。完整检查点支持部分历史；稳定 id 保留任务身份，计划回放保留被移除的步骤。详情注册在现有侧栏中。查看偏好保留在 Session 作用域内，不进入持久日志。

## 考虑过的替代方案

- 单独的规划工具会把 agent 的任务列表分给两个所有者，并要求重复更新。
- 每个 agent 对应一个节点会遗漏主 agent 工作和尚未开始的步骤。
- 从阶段或时间戳推断连线会在缺少证据时声明前置依赖。
- 为展示当前工作引入新执行调度器，会同时改变取消、重试与副作用保证。

## 影响

既有紧凑列表仍然有效，详细计划则增加调用参数的 token 用量。每次更新都必须保留 id 与相关元数据。执行证据目前覆盖已记录的工作流成员；单独的普通任务状态仍是计划声明。节点级重试与计划编辑需要各自的执行语义。
